# AGENTS.md

Webhook catcher + visual router. Requirements live in `SPEC.md`, usage in `README.md`.

## Shape
- Native PHP 8.3 (no Composer, no framework) + php-fpm, Vue 3 `<script setup>` + Vite + Pinia + Tailwind v4, Postgres 16, nginx.
- **Ingestion is asynchronous**: `api` stores the request, records `pending` rows in `workflow_runs` and answers `202` with `queued: N`. A separate `worker` service claims those rows (`FOR UPDATE SKIP LOCKED`), evaluates conditions and runs actions. A slow forward target therefore cannot delay the sender.
- `workflow_runs` is both the journal and the queue (`pending`/`running`/`success`/`failed`/`skipped`, `attempts`, `available_at`, `locked_at`). `workflow_run_steps` logs one row per action per attempt (HTTP status, response body, duration). Transient failures (network, timeout, `408`, `429`, `5xx`) are retried with exponential backoff; a retry skips actions that already succeeded, so a forward is never sent twice.
- **Conditions are a tree**, not a flat AND list: `workflows.conditions` is `{"mode":"all"|"any","rules":[…]}` where a rule is either a condition or another group (depth ≤ 5, ≤ 40 leaves). A plain list from an older client is normalized to `{mode:"all"}` by `WorkflowEngine::normalizeTree` and `WorkflowsController::validTree`, so `type = payment AND (name = Ada OR name = Bob)` is expressible. `condition_count` (leaf count, not groups) is derived on read.
- **`priority` + `stop_processing` turn rules into routing**: `WorkflowEngine::enqueue` queues matching workflows `ORDER BY priority DESC, id` (0–1000), and a **successful** run of a `stop_processing` workflow marks the request's remaining `pending` runs `skipped` with a message naming the stopping scenario. `failed` and `skipped` outcomes never stop anything.
- **`delay` action**: pauses the run, not the sender. `WorkflowEngine::rescheduleIn` moves `available_at` forward and returns `running` without consuming `ROUTING_MAX_ATTEMPTS`; the delay step is recorded as `success`, and the resumed pass skips it through the same `$done` set that protects a `forward`.
- **Dry run**: `POST /api/requests/{id}/preview` evaluates conditions and *describes* actions (URL, method, headers, body, signature, resolved `UrlGuard` verdict) without queueing or sending. A body with `{conditions, actions}` previews an unsaved draft; an empty body previews every enabled rule of the room.
- **Health is real**: `GET /api/health` (public) checks database, queue (oldest `pending` older than `HEALTH_QUEUE_MAX_AGE`), and worker liveness through `worker_heartbeats` (`WORKER_STALE_SECONDS`). `503` = not ready. A missing heartbeat is only a failure when `pending` work exists, so a fresh volume is not red before the worker's first loop. `bin/healthcheck.php` is the CLI twin used by the compose healthcheck, because the `api` container does not listen on HTTP.
- **`GET /api/runs`** lists runs directly (`room`, `status`, `workflow_id`, `q` over run message / workflow name / request path), which is the "what failed in the last hour" question; `RunsView.vue` is its page.
- **`GET /api/analytics`** answers "how did it behave" where `stats` answers "how many right now": volume per hour, the outcome mix, and p50/p95/max per action type from `workflow_run_steps` (the only place a 4-second forward that still ended `success` is visible). `hours` is clamped to 1–168 and `0` means the 24h default; the timeline has one bucket per hour **plus the hour in progress** (N+1) and includes silent hours as zeroes. `success_rate` divides `success` by **finished** runs only and is `null` when nothing finished. `AnalyticsView.vue` is its page.
- **`GET /api/metrics`** is the installation as Prometheus text (`text/plain; version=0.0.4`) — queue depth, runs by status, worker heartbeat, open breakers. Public like `/api/health` (a scrape config has no credentials) and numbers only: no payload, no room slug, no forward address, no secret. `hookdock_breaker_open` is a count with no `address` label for exactly that reason.
- **Search covers the header block**: `RequestsController::filters()` adds `r.headers::text ILIKE :q_headers`, so "did any delivery carry `X-GitHub-Event: push`" is a query instead of opening rows one by one.
- UI updates arrive over WebSocket, not polling: `api`/`worker` publish `pg_notify` → `ws` container broadcasts. There is no refresh timer in the SPA.
- UI copy is Russian (`ru-RU` dates). Keep new strings and validation messages Russian, including API errors shown in the UI.
- Light theme is the default; `.dark` on `<html>` switches themes. Colors are CSS variables in `frontend/src/assets/main.css` (surfaces, text, lines) exposed as Tailwind tokens (`bg-surface`, `text-ink`, `border-line`). Do not hardcode `slate-*` surfaces in new UI.
- Native controls are wrapped: `frontend/src/components/ui/{AppInput,AppSelect,AppCheckbox,AppToggle,AppTextarea}.vue`. Use these instead of raw `<input>/<select>/<textarea>` so both themes, focus rings and sizes stay consistent.
- Native `window.alert/confirm/prompt` are never used: `notify(message, { tone })` shows a corner toast and `await confirm({ title, message, confirmLabel })` opens a themed dialog (`composables/dialog.js`, mounted once as `ui/AppToast.vue` + `ui/AppDialog.vue` in `App.vue`). Add new cases there instead of a browser popup. `AppDialog` is `z-[80]` — deliberately above toasts (`z-[60]`), `AppSelect`'s listbox (`z-[70]`) and every form/drawer (`z-50`), because equal `z-index` is resolved by DOM order and `AppDialog` is mounted before the modals, so at `z-50` a confirmation painted *under* the form that raised it.
- Manual refresh buttons use `composables/useRefresh.js`: `const { busy, updatedAt, run } = useRefresh(() => load())`, then `:disabled="busy"` + `<AppSpinner size="xs" />` in the button and «обновлено HH:MM:SS» from `formatClock`. `run` holds `busy` for ≥350 ms so the click is visible on a fast local API. Realtime reloads call the loader directly with `{ silent: true }` and must not touch that state.
- **One visible loader per surface.** A list has several independent "waiting" sources (initial load, user reload held for `BUSY_MIN`, refresh button) and they overlap, so derive both the overlay and the inline spinner from a single predicate — `RequestsView` uses `listLoading` + `showOverlay`/`showInlineLoader`, which are mutually exclusive by construction. Do not let a component render two indicators for one action: the method select used to show its own spinner next to the table's, and an empty room used to show the overlay over the inline spinner at once. Do not reintroduce a "did the list have rows when the reload started" snapshot — it disagrees with the current list while a room switch is in flight and produces exactly that double.
- **The requests log has one data source and two layouts.** The 7-column table renders at `md` and up; below it the same `items` render as a `<button>` card list (method + path on the first line, time · endpoint · size on the second, routing counters on the third). Do not duplicate the rows into a second fetch or a second loader: the empty state and the inline spinner live **outside** both branches, so switching layouts cannot produce two indicators. Anything added to the table row belongs in the card too — a column nobody can see on a phone is a bug, not a simplification.
- Switching rooms must clear `items`/`stats` and skip the filter-reset reload: resetting `filters` trips the `filters` watcher, so `RequestsView` sets `suppressFilterReload` **only when a filter actually differs** from its default (writing an unchanged value does not trigger the watcher, and a stale flag would swallow the user's next real change). Saved filters (`wr_filters`, one entry per room, in `localStorage`) are restored through `applyFilters()`, which resets and reassigns in one tick and returns whether anything moved — that return value *is* the flag, so an unchanged set cannot leave a stale suppression behind. The set is persisted from the debounced filter watcher, never from `applyFilters`, and a default set is deleted rather than stored so «Сбросить» stays effective on the next visit. Saved values are normalized against the known methods/periods: a stale entry must not render the select as «Все» while the request stays filtered. Overlapping `load()` calls are resolved with a `loadSeq` counter — a superseded response must not repaint and its `finally` must not clear `loading` for the newer one. A room switch during a filter reload otherwise fires four requests and can paint one room's rows under another's heading.
- `AppSelect` is not a native `<select>`: the trigger is a `role="combobox"` button and the option list is teleported to `<body>` with `position: fixed` (keyboard nav, outside-click close, flip-up near the viewport edge, reposition on scroll). Pass `:options="[{ value, label }]"`; do not expect native `<option>` slots or OS dropdown styling. A `<datalist>`-backed `<input>` is the same mistake in a different shape: the endpoint filter used one, and the OS drew a system-font list that ignored the theme and the surrounding controls. Any "pick one of N" filter is an `AppSelect`; its options may be derived (and must include the currently selected value even when it is not in the source list, or the select renders as "Все" while the list stays filtered).
- **A long option list is searchable, not scrollable.** `AppSelect` with `searchable` renders a `role="searchbox"` field inside the panel and emits `@search` (debounced 250 ms, Enter searches at once); the caller decides where matches come from. `RequestsView` uses that split for the endpoint filter: the closed list is the room's 15 most frequent endpoints from `stats` (`endpoints_limit`), the rest come from `GET /api/endpoints?room=&q=` — the same "page + search" model as the room sidebar, so hundreds of paths stay reachable. Do not grow the page to "everything": the panel would cover the whole log. The term is reset on close and on a room switch (one room's endpoints say nothing about another's), and a truncated list must say so (`Показаны 15 из 40 — остальные через поиск`) or it reads as complete. `Escape` in the search field has to call `close()` itself — `@keydown.stop` on the field otherwise hides the trigger's handler and the panel never closes.
- `AppCheckbox` has an `indeterminate` prop for the "some, not all" state a "select all" header needs. Native checkboxes expose that only as a DOM property, so it is drawn from the prop (the `peer`-styled box shows a dash and `aria-checked="mixed"`); do not bind `:indeterminate.prop` on a raw input and expect the wrapper to follow. The selection itself lives in `RequestsView` as an id list and is pruned to the visible page on every load, because a tick that outlives its row lets «Удалить выбранные» act on something nobody can see.
- `backend/public/index.php` is the only PHP entrypoint. nginx routes `~ ^/(api|hook)/` to fpm and everything else to `index.html`, so PHP never renders HTML and SPA deep links work.
- No global auth middleware: each dashboard route calls `Auth::requireUser($request)` itself (`Auth::requireUser($request, true)` in every mutating handler, so a `scope: read` token **and** a `viewer` account are refused with `403`), and `/api/users*` adds `Auth::requireAdmin()`. Webhook routes and `/api/health` are intentionally public — do not wrap them.
- **Roles, audit and version history** (migration `013`): `users.role` (`admin`/`editor`/`viewer`) limits the person and is read from the table on every request, `scope` limits the token; both are enforced. Every mutation appends to `audit_log` (denormalized, secrets redacted before the diff) and every workflow save writes a `workflow_versions` snapshot, so "who changed it" and "what did it look like" are answerable. A restore is a new `rollback` version rather than a rewrite.
- Ingestion stores the request, records `pending` runs, publishes `request.created` and returns `202`; `Services\WorkflowEngine` is not executed in the request. `worker` claims runs, so an unreachable forward target can never hold the sender. A failed action never changes the already-sent `202`.
- **Optional HMAC per room**: `rooms.secret` is set with `POST /api/rooms/{id}/secret` and cleared with `DELETE`; the catcher verifies `X-Hookdock-Signature` (`Support\Signature`) **before** the `INSERT`, so an unsigned/forged request is neither stored nor queued. Room responses expose only `has_secret`; the secret itself is returned once, at issue time. A room without a secret stays public.
- **Replay protection is opt-in per room**: `rooms.require_timestamp` makes `X-Hookdock-Timestamp` (unix seconds) mandatory and the digest covers `"<ts>.<body>"`, with a `SIGNATURE_TOLERANCE_SECONDS` (300) window. `Signature::verify` uses the timestamped form **whenever the header is present**, even if the room does not require it — falling back to body-only would let a captured request be replayed by keeping its timestamp, which defeats the point. `timestamp` is compared as text because the sender signed those exact bytes. The flag without a secret verifies nothing, so such a room stays public instead of rejecting every delivery.
- **Idempotent delivery is opt-in per room**: `rooms.dedup_header` names the header whose value is the delivery id (`X-GitHub-Delivery`, `Stripe-Event-Id`, …). The check is the partial unique index `incoming_requests_dedup_uniq` on `(room_id, dedup_key) WHERE dedup_key IS NOT NULL`, caught as `23505` — a preceding `SELECT` would let two concurrent deliveries of one event both be "first". The repeat **is stored** with `duplicate_of` (the log must show that the sender retried) but is **not queued**, and the answer stays `202 {duplicate: true, queued: 0, duplicate_of: <id>}`: a `409` would make the sender retry the delivery it was told to stop sending. A configured header the sender did not send is not an error — the delivery is handled like any other, so enabling dedup cannot break an old integration. `dedup_key` is capped at 200 chars (`VARCHAR(200)`), and `duplicate_of` is a self-FK with `ON DELETE SET NULL` plus its own index, because retention and a room delete clear parents in batches.
- **Room delivery settings follow "omitted keeps"**: `PUT /api/rooms/{id}` keeps `dedup_header`/`require_timestamp` when the key is absent and turns deduplication off on `dedup_header: ""`, exactly like `endpoint`. A rename form must not silently disable a setting it does not show.
- **Replay and manual retry**: `POST /api/requests/{id}/replay` queues the room's matching workflows again for the stored row (no new `incoming_requests` row); `POST /api/runs/{id}/retry` inserts a fresh `workflow_runs` row for the same workflow/request, leaving the failed one with its attempts and steps. Export: `GET /api/requests/export` streams `json`/`ndjson`/`csv` with the same filters as the list. `GET /api/requests/{id}/body` downloads the original `raw_body` as a file; `POST /api/workflows/{id}/duplicate` copies a rule, paused. **`POST /api/requests/{id}/redeliver`** is the counterpart for "the payload was wrong": it stores a *copy* with corrections (`replayed_from`, never `duplicate_of`, no `dedup_key`) and routes it, so the original row — the evidence of what the sender actually sent — is never mutated. **`POST /api/requests/bulk`** takes an explicit `{action: delete|replay, ids: [...]}` (cap `BULK_MAX` = 200) rather than the current filter, and skips a row whose run is still `pending`/`running` (deleting it would cancel routing in progress), reporting it in `skipped`; ids that no longer exist land in `missing` instead of failing the batch. One audit entry per call (`request.bulk_deleted`/`request.bulk_replayed`).
- **Signed forwards**: a `forward` may carry `secret`, which signs the outgoing body the same way the catcher verifies incoming ones (`X-Hookdock-Signature`, `Support\Signature`). Stored inside `actions[]`, so like `rooms.secret` it is never echoed back — reads expose `signed: true` instead. Because the editor therefore never sees the value, an empty `secret` on save means "keep the stored one" and removal is the explicit `clear_signature: true`; the previous secret is carried over only when the action index **and** the URL match, so reordering forwards cannot move one target's secret onto another. `sign_timestamp` (default `false`) adds `X-Hookdock-Timestamp` and signs `"<ts>.<body>"`; it is opt-in because a recipient that verifies a body-only HMAC would reject the new form. `actions[].timeout` (1–60, `422` otherwise) overrides `FORWARD_TIMEOUT`; the key is omitted when unset rather than stored as `0`, and `HttpClient::send` clamps it so one action cannot hold a queue slot for as long as it asks.
- **Read-only tokens**: `POST /api/auth/read-token` (requires a full `scope: api` token) issues a `scope: read` JWT for dashboards and colleagues. Reads, exports, previews and the run journal work; every mutating handler answers `403` «Токен только для чтения…». A read token cannot mint another one. `GET /api/auth/me` returns `scope` so the SPA can hide mutating buttons.
- **Roles** (`users.role`, migration `013`): `admin` / `editor` / `viewer`, default `admin` for existing rows. A role is read from `users` on every request and is **not** put into the JWT, so a demotion applies on the next request instead of when the 12h token expires. Role and scope are separate limits and both are enforced: `Auth::requireUser($request, true)` refuses `viewer` and `scope: read` alike, `Auth::requireAdmin()` guards `/api/users*` (an editor who could grant themselves `admin` makes the roles decorative). `GET /api/auth/me` returns `role`, `can_write` and `can_admin`; the SPA hides what it cannot use, but the server is what enforces it.
- **Audit journal** (`audit_log`, `GET /api/audit`): append-only and denormalized — `actor_email`, `actor_role`, `room_slug` and `object_label` are copies, FKs are `ON DELETE SET NULL`, so an entry stays readable after a rename and a room delete. `changes` is `{field: [before, after]}`; `Audit::shape()` keeps a nested value up to `MAX_INLINE_BYTES` (600) verbatim, because «conditions changed, 1 rule» is true and useless, and summarizes anything larger; a diff over `MAX_CHANGES_BYTES` (4000) becomes a size marker. Secrets are redacted **before** the diff is built (`redactActions()`), so a signature secret cannot reach the table at all. `Audit::record` is best-effort (failures only reach `error_log`): the change is already applied, so a `500` would report that nothing happened.
- **Workflow versions** (`workflow_versions`): every save stores `conditions` + `actions` as a snapshot (the list returns the newest 100), `013` writes a `baseline` for rules that predate history. A restore is a **new** version (`change: 'rollback'`), never a rewrite — the current state is snapshotted first, so the rollback itself can be undone, and deleting intermediate rows would make «who put this back and when» unanswerable. Snapshots keep signature secrets (otherwise a restored signed forward would send unsigned) and reads pass through `redactActions()`, so the value still never leaves the API. `actions_version` follows the normal save rule on a rollback: it grows only when the action list really differs.
- **Passwords**: length only, 8–72 bytes. Composition rules are deliberately absent (they produce `Password1!`), and the upper bound is bcrypt's silent truncation point, not decoration. `POST /api/auth/password` requires `current_password` — a stolen token must not be a permanent account takeover — and needs no admin role; `PUT /api/users/{id}` with `password` is the admin reset. Only the fact of the change is journalled, never the hash or the value.
- **Circuit breaker per forward address**: state lives in `forward_targets`, keyed by `CircuitBreaker::address()` (`scheme://host:port`) and **not** by workflow — two rules forwarding to one endpoint share a verdict, and fixing the endpoint fixes both. It is installation-wide for the same reason (`GET /api/breakers` is not room-scoped). `state` is derived from `next_probe_at` (`open` refuses, `half_open` lets exactly one probe through, `closed` is normal), so recovery needs no background process: the first delivery after `FORWARD_BREAKER_COOLDOWN` is the probe. `CircuitBreaker::record()` is called in `WorkflowEngine::execute()` **only when `!$willRetry`** — counting every attempt would open the breaker during one blip — and it is called **before** the `delay`/defer branches, because those return early and a forward that succeeded in the same pass must still close the breaker. `CircuitBreaker::peek()` exists for the dry run so a preview can describe the state without consuming the single half-open probe. A refused address records a `skipped` step and **defers** the run (`rescheduleIn(..., $deferred: true)`) instead of failing it: the target was never called, and a `failed` would pause the very rule that would recover with it. `POST /api/breakers/reset` deletes the row rather than setting it to `closed`, because a kept failure count would re-open it on the next error and the reset would look like it did nothing.
- **A deferred run has no natural end**, because a deferral is not an attempt, so `workflow_runs.deferrals` bounds it: after `WorkflowEngine::deferralLimit()` (`FORWARD_BREAKER_DEFERRALS`, 3) cooldowns the run is finished `skipped` with the reason instead of staying `pending` forever. `claim()` must keep returning `deferrals` — dropping it from the `RETURNING` list silently disables the limit. `deferrals` is also selected by `RequestsController` and `RunsController` so the journal can explain a run that waited.
- **Optimistic locking of the action list**: `workflows.actions_version` is what the editor loaded; `PUT /api/workflows/{id}` with a different value answers `409` plus `error.actions_version`, because the last save used to silently replace the other tab's whole action list — including a forward it had just added. The version only grows when the actions actually change (`WorkflowsController::fingerprint()`, a canonical JSON comparison), so renaming a rule does not make another tab's draft stale. Omitting the field (curl, an old script) skips the check; requiring it would break every existing integration for a protection it never asked for.
- **Export/import of a room's rules**: `GET /api/rooms/{id}/workflows/export` writes a `hookdock.room` document (`version: 1`), `POST /api/rooms/{id}/workflows/import` creates rules from it. Secrets never travel: reads expose `signed: true`, and the import reports `secrets_not_imported` (counted over the **document**, because normalization drops `signed`), otherwise the imported rule would look right and send unsigned requests. `room_id` comes from the URL, never the document, so a staging export cannot write into production by naming it. The import is all-or-nothing, only adds (a colliding name gets a numeric suffix — importing the same file twice is a normal check), and caps at `MAX_IMPORT` (50) rules.
- **Rooms** partition everything: `incoming_requests.room_id` and `workflows.room_id` are NOT NULL FKs with `ON DELETE CASCADE`. Webhook URL is `/hook/{room}/{endpoint}` (and `/api/webhook/...`); legacy `/hook/{endpoint}` lands in the seeded `default` room («Общая»). `rooms.endpoint` is the room's advertised endpoint (`hook-xxxxxx`); it is copied into UI addresses but does not restrict ingestion. Slug→room resolution is `Services\RoomResolver`; `WorkflowEngine` filters `WHERE enabled AND room_id = :room_id`, so a workflow never fires for another room.
- `body`/`headers`/`query` are `jsonb`. `body` is NULL for non-JSON payloads; the original text stays in `raw_body`.
- Migrations: `backend/migrations/*.sql`, tracked in `schema_migrations`, applied by `backend/migrate.php` from the api entrypoint on every boot. Add a new numbered file; never edit an applied one.

- The breaker in `scripts/smoke.ps1` is state that survives a run, so the suite resets `http://web:9999`, `http://web:9998` and `http://web:80` right after login and again before the manual-retry block. Without that, a leftover open address turns a later "the retry path failed twice" assertion into a correctly-deferred run. Use a distinct port for each path that needs a fresh failure count (`9999` for retries, `9998` for the transformed-payload retry, `80` for the 4xx breaker test), because the key is the address.

- `scripts/smoke.ps1` now asserts JSONB columns arrive as arrays/objects, that a paused workflow can be created, that rooms isolate requests and workflows, that the rooms list is a page (`meta.total`/`has_more`) with a working `q`/`slug` lookup, and that repeated terminal failures pause a workflow (`auto_paused`, `disabled_reason`, `workflows_auto_paused`) while re-enabling resets the streak.
- `scripts/smoke.ps1` is **UTF-16LE with a BOM** — read and write it with `[System.Text.Encoding]::Unicode` / `New-Object System.Text.UnicodeEncoding($false, $true)`, never as UTF-8, or every Russian string in it is mangled. Keep assertions ASCII where the host is Windows PowerShell 5.1: it sends a non-ASCII body as `?`, so a test that compares Russian text passes in pwsh 7 and fails under 5.1.
- Header assertions must join before comparing: in PowerShell 7 `$response.Headers["X"]` is a **string array**, so `-like` returns an array and `Assert-True` throws "Cannot convert System.Object[] to Boolean". Write `(@($r.Headers["X"]) -join "; ") -like "…"`; the same file then passes on 5.1 and 7.
- The suite must pass in **both** host PowerShells: `powershell -ExecutionPolicy Bypass -File scripts/smoke.ps1` and `pwsh -NoProfile -File scripts/smoke.ps1`. CI uses pwsh (Linux runners), so a 5.1-only fix is not verified.
- `.github/workflows/ci.yml` runs on push to `main` and on every PR: one job for `npm ci && npm run build` in `frontend/`, one that does `docker compose up -d --build`, waits for `api` to report `"Health":"healthy"` (which means migrations ran) plus `web` running, then runs `scripts/smoke.ps1` under `pwsh`. There is no bash twin of the smoke script — do not add a second suite, extend the PowerShell one.
- `docs/openapi.yaml` is the contract and `postman/collections/Hookdock API/` is the runnable twin. A new endpoint means both: the spec (paths + schemas) and a request file with its assertions. Verify with `python -c "from openapi_spec_validator import validate; ..."` and `postman collection lint "postman/collections/Hookdock API"`. `postman spec lint` and collection `ai-readiness` need `postman login`; `collection lint` and `collection run` work anonymously.
- **Postman collection folder order comes from `order` in each folder's `.resources/definition.yaml`**, and a folder without one sorts alphabetically. Login must run before anything that needs the token, `Export room rules` must run before `Import room rules` (it captures the document), and `Ingest` must run before `Requests`/`Runs` (it creates the row they read), so every folder carries an explicit `order` (Auth 1000 → Access 1500 → Rooms 2000 → Workflows 3000 → Ingest 4000 → Requests 5000 → Runs 6000 → Delivery 7000 → Cleanup 9000). Within `Workflows`, `Stale save is refused` sits at 3500 — after `Create workflow` (2000) has captured `workflow_id` but before the signed forward is edited; `Workflow versions` (3200) and `Restore a version` (3300) sit before it because the stale-save test needs a rule whose lock is unchanged. `Access` creates an account per run with a `run_suffix`-based email and `Cleanup / Cleanup user` deletes it, because a fixed address would answer `422` on the second run and leave `Change role` with nothing to promote. A collection-level `http:beforeRequest` script cannot log in instead: `pm.environment`/`--env-var` values are not visible there (`base_url` is `undefined`) and `pm.sendRequest` callbacks do not complete before the request is sent.
- A collection request that needs a variable another request may not have set must `pm.execution.skipRequest()` in `beforeRequest` rather than send the placeholder: `POST /api/runs/{{run_id}}/retry` with no captured run otherwise answers a 404 that says nothing about the API. `Runs / Run journal` falls back to the newest run of any status, so `retry` asserts `202 | 422` (422 = still queued). `Delivery / Reset breaker` is the exception that does **not** skip: with no open address it sends a `.invalid` placeholder and asserts `reset: false`, because the no-op is a documented answer and skipping would leave the endpoint unexercised.
- The Postman sandbox only has `CryptoJS` for HMAC: `crypto` is WebCrypto (no `createHmac`) and `require('crypto')` cannot resolve, so the "CryptoJS is deprecated" notice in a run is cosmetic and the `CryptoJS.HmacSHA256(...).toString(CryptoJS.enc.Hex)` form is the one that works.
- A v3 `queryParams` list must match the query string in `url` exactly (lint error `FMT209`), including every enabled and disabled parameter. Adding a filter to the YAML means adding it to both places.

## Gotchas
- `/api/requests/export` must stay registered **before** `/api/requests/{id}`: the `{id}` pattern matches any single segment, so `export` would be read as a request id and answered with 404. `/api/requests/bulk` has the same requirement for the same reason — registered after `{id}`, a bulk delete would be answered `404` for a request id of `bulk`.
- A redelivery is **not** a duplicate delivery. `replayed_from` marks a copy an operator sent with corrections and such a row **is** routed; `duplicate_of` marks a sender's repeat that was deliberately not routed. The copy gets no `dedup_key` — inheriting the original one would make the room's dedup index treat the redelivery as a repeat of itself and store it without queueing anything, which looks like "the corrected payload matched no rules".
- `RequestsController::redeliver()` must `JsonColumns::decode($original, ['query', 'headers', 'body'])` the fetched row **before** merging: PDO returns jsonb as a string, `is_array($original['headers'])` is then false, and the copy silently loses `content-type` and every other header the original carried — the failure is invisible in the response and only shows up as a rule that stopped matching.
- A bulk operation takes an explicit `ids` list, never the current filter: the rows a filter matches can change between the click and the request, and the log has no undo. A row with a `pending`/`running` run is skipped with a reason (deleting it would cancel routing in progress) — so a smoke assertion on a partial batch needs `Wait-ForRuns` first, or the previous batch is still in flight and the count is zero for the wrong reason.
- A manual retry (`POST /api/runs/{id}/retry`) inserts a **new** `workflow_runs` row instead of resetting the failed one. Resetting would make `succeededSteps()` skip the actions that succeeded before the failure, so «Повторить» would silently not repeat them. The failed row keeps its attempts and step log as evidence.
- The export reuses `RequestsController::filters()`, the same clause as the list — a separate query drifts and a download stops matching the screen. CSV is `;`-separated with a UTF-8 BOM (Excel + ru-RU); JSON/NDJSON are written row by row instead of being assembled as one string in PHP (libpq still buffers the result set).
- `rooms.secret` is stored as-is because HMAC cannot be verified against a hash, but it is **never** returned by the API: `RoomsController` selects `(secret IS NOT NULL) AS has_secret` and the value is shown only in the response that issues it. Do not add `secret` to a room `SELECT` echoed to the SPA. There are exactly two responses that carry it: `POST /api/rooms/{id}/secret` and `POST /api/rooms` with `require_signature: true` — the latter issues it inside the same `INSERT`, so a room is never listed as public after an operator asked for a signature (a "create, then POST /secret" pair leaves exactly that window when the second call fails). `insert()` builds the column list conditionally instead of `CASE WHEN :secret IS NULL`, because native prepared statements cannot infer the type of a bare `:secret IS NULL` and Postgres answers "could not determine data type".
- `docker/php/Dockerfile` must keep `libpq` installed at runtime; removing `postgresql-dev` without it breaks `pdo_pgsql` with a missing `libpq.so.5`.
- `Auth::user()` rejects a token whose `scope` is set and is not `api`. The 60s websocket ticket has `scope: ws` and travels in a query string, so accepting it here would turn it into a full API credential. Login issues `scope: api`; older unscoped tokens still work.
- `Support\UrlGuard` guards `forward` URLs before the request and compares **packed bytes** (`inet_pton`), never text: `::1`, `0:0:0:0:0:0:0:1`, `::ffff:7f00:1`, `::ffff:127.0.0.1` and `::ffff:a9fe:a9fe` are the same handful of addresses in different spellings, and a string check lets all but the first through. Refused: `0.0.0.0/8`, `127/8`, `169.254/16` (cloud metadata), multicast/broadcast, `::`, `::1`, `fe80::/10`, `ff00::/8`, and any IPv6 form that embeds a refused IPv4 (`unwrapV4`). A refused URL fails the run terminally (no retry). Resolution unions `gethostbynamel` (the only one that sees `/etc/hosts`, i.e. Docker service names and `ip6-localhost`) with `dns_get_record` A+AAAA, and is **fail-closed**: a name that does not resolve is refused, because it is resolved again at connect time (`ip6-localhost` reached `::1` with no DNS record at all). RFC1918 and `fd00::/8` stay allowed because `http://web/...` is a normal target. `FORWARD_ALLOW_INTERNAL=1` restores the old behaviour; `FORWARD_BLOCKED_HOSTS` adds hosts.
- `Support\HttpClient` runs on curl with `CURLOPT_RESOLVE` pinning the host to the exact addresses `UrlGuard` approved — a DNS-rebinding name cannot pass the check as public and connect as `127.0.0.1`. Redirects are not followed (`FOLLOWLOCATION => false`) because they would leave the pinned address, and `CURLOPT_PROTOCOLS_STR` is limited to `http,https`. Bodies are truncated at 4 KB.
- `Support\RateLimiter` uses a `rate_limits` table (fixed window, one row per bucket/subject/window) and **fails open**: a broken limiter must not lock the operator out. Login is limited per account (`LOGIN_MAX_ATTEMPTS`, 10/min) and, more loosely, per address (`LOGIN_IP_MAX_ATTEMPTS`, 50/min) — a strict per-IP cap locks out a whole NAT before it slows an attacker. The catcher limit (`INGEST_MAX_PER_WINDOW`) is 0 = unlimited by default so an upgrade never starts dropping real traffic.
- `Request::clientIp()` trusts `HTTP_X_REAL_IP`, which nginx sets from `$remote_addr` via `fastcgi_param` (it overwrites any client value). `X-Forwarded-For` is ignored on purpose. Without this every request looks like it came from the nginx container.
- Retention runs in the worker (`pruneIfDue()` at the top of every loop pass, **not** in the idle branch — a continuously busy worker would otherwise starve it) and under `--once` too, hourly (`RETENTION_INTERVAL_SECONDS`), in batches of 1000. `RETENTION_DAYS=0` (default) keeps everything — an audit log is the product's point. Only finished runs are pruned; `pending`/`running` rows are never touched, and a request that still has a queued run is skipped (`NOT EXISTS`) so housekeeping cannot cascade a delivery away.
- The `q` filter must keep `raw_body ILIKE :q` without `COALESCE`: the trigram index (`incoming_requests_raw_body_trgm_idx`, migration `006`) only matches the bare column, and a function wrapper turns search back into a sequential scan. `pg_trgm` is created by that migration; `007_search_indexes.sql` adds the same trigram indexes to `path` and `endpoint`, and `015` one on `headers::text`, so all four branches are indexable. The header branch must stay a **cast** (`r.headers::text`), not `jsonb_array_elements` and not a helper function — the index is declared on that exact expression. The value itself is escaped (`%`, `_`, `\` are LIKE metacharacters) — a literal `ESCAPE '\'` clause must not be added, because PDO's parser reads `\'` as an escaped quote and then fails to bind the remaining placeholders (`HY093`); backslash is Postgres' default LIKE escape anyway.
- The login page has no credentials in the bundle. `/api/auth/config` (public) returns the demo account only when `DEMO_LOGIN=1`, plus config warnings (`JWT_SECRET` left at its default).
- `docker/php/php.ini` keeps `enable_post_data_reading = Off`. With it on, PHP consumes `multipart/form-data` into `$_POST` and `php://input` is empty, so the catcher stores every multipart webhook with no body. `$_POST`/`$_FILES` are unused in the backend — do not turn it back on.
- The catcher is matched by prefix in `backend/public/index.php` (`isWebhookPath`), not by router patterns: an endpoint may carry its own path (`/hook/{room}/{endpoint}/a/b/c`) and a pattern can only match a fixed number of segments. Only `/api/webhook` and `/hook` at a segment boundary count, so `/api/webhookX` is not the catcher.
- CORS preflight on the catcher is answered in `index.php` (`respondToCors`) only when `Access-Control-Request-Method` is present. A genuine `OPTIONS` webhook (no such header) is still stored like any other method.
- Build context is the repo root. `.dockerignore` excludes `node_modules`, `dist`, `scripts`; keep it lean — the checkout is OneDrive-synced and large contexts are slow.
- Container-bound scripts and nginx config need LF line endings.
- Tailwind v4 has no `tailwind.config.js`/PostCSS: theme is in `frontend/src/assets/main.css`, wired through `@tailwindcss/vite`.
- `{{ … }}` in Vue text is interpolation. For literal placeholders in UI hints use `v-pre` (see `WorkflowEditor.vue`).
- JWT is HS256 in `localStorage` (`wr_token`); `frontend/src/api/client.js` clears it and fires `auth:expired` on 401.
- Seeded admin `admin@hookdock.local` / `123456` is a bcrypt hash in `001_init.sql`; `004_admin_email.sql` renames the account on an existing volume. Editing `001_init.sql` alone will not update a volume that already has the old address.
- Bind `jsonb` params as JSON-encoded strings (see `WebhookController`), not PHP arrays.
- PDO/pgsql returns `jsonb` columns as strings. Decode them at the API boundary with `Support\JsonColumns::decode()`, otherwise the SPA receives a string where it expects arrays (`conditions`, `actions`, `headers`, `query`, `body`).
- Boolean columns need string params (`'true'`/`'false'`), not PHP booleans: `false` is sent as `''` and Postgres rejects it (`invalid input syntax for type boolean`).
- Forward actions call URLs from inside the `worker` container: use service DNS (`http://web/...`), not `localhost:8080`.
- nginx needs `location = /api/ws` (exact) for the websocket: `^~ /api/ws` would swallow `POST /api/ws/ticket`, and a plain prefix would lose to the `~ ^/(api|hook)/` regex.
- The `ws` and `worker` containers run with `RUN_MIGRATIONS=0`; only `api` applies migrations, otherwise the boots race on `schema_migrations`. `worker` waits for the schema at startup and `depends_on: api`, so it cannot crash-loop on a cold start.
- `backend/bin/worker.php` and `ws-server.php` load `src/autoload.php`, not `bootstrap.php` — bootstrap installs an HTTP exception handler that calls `exit`.
- nginx keeps the `resolver 127.0.0.11` directive and proxies through variables (`set $api_upstream api:9000`). Without it, a recreated `api`/`ws` gets a new IP and nginx answers 502 until `web` is restarted.
- Never write frames to a client that has not finished the handshake (a heartbeat ping before `HTTP/1.1 101` breaks the upgrade). `WebSocketServer::heartbeat()` skips non-open clients.
- `Realtime::publish` is best effort: catch and `error_log`, so a notify failure cannot turn a stored webhook into a non-202 response. Payloads are ids only (Postgres caps `NOTIFY` at 8000 bytes).
- Retries only cover transient failures (`HttpClient::retryable`: transport error, `408`, `429`, `5xx`). A retry skips actions recorded as `success` in `workflow_run_steps` — except `transform`, which is pure and must re-run so a later `forward` with `payload: "transformed"` still has data. Anything that must never repeat (a `forward`) belongs behind that check.
- The breaker learns from the **terminal** verdict, so it sees two different kinds of evidence: a `4xx` that is never retried, and a `5xx`/timeout that survived the whole retry budget. A dry run must call `CircuitBreaker::peek()` and never `tryAcquire()` — a preview that consumes the single half-open probe pushes the real attempt back by a full cooldown and the dashboard starts lying about it.
- Analytics bucket by **UTC in Postgres** (`date_trunc('hour', ts) AT TIME ZONE 'UTC'` → `to_char`), never by leaving a `timestamptz` for PHP to key on: the session timezone decides what "hour" means, and the keys built in PHP would silently miss every row on an installation whose database runs in another zone. The keys are built the same way (`Y-m-d\TH:00:00\Z`) so a missing bucket is a genuine quiet hour and not a formatting mismatch. Every query shares one `since`, so the chart and the breakdowns cannot describe two slightly different windows.
- `success_rate` divides by **finished** runs (`success + failed + skipped`), and `skipped` counts as finished: a deferred run that hit the breaker limit never called its target, so leaving it out of the denominator would inflate the rate. `pending`/`running` are excluded, and `null` (not `0`) is returned when nothing finished — a queued backlog must not read as a 0% success rate.
- The Prometheus exposition writes `# HELP`/`# TYPE` **once per metric name**: `MetricsController::add()` looks for the header line before appending, and repeating the pair per labelled series makes a scraper reject the whole payload. `hookdock_runs` is emitted by hand (one line per status) for that reason. A metric that must stay unlabelled stays unlabelled — `hookdock_breaker_open` carries a count, because a forward address is an internal hostname and a public scrape must not learn it.
- `MetricsController::show()` answers `503` while still writing every metric it could read: a scraper's own health check reads the status code, but a broken check must not blank the numbers that still work. It `exit`s after echoing, so it cannot fall through to the router's JSON handling.
- `WorkflowEngine::runActions()` returns a 6-tuple `[$status, $message, $retry, $delay, $defer, $breakerOutcomes]`; every caller must destructure all six. `$breakerOutcomes` is `[address, ok, status, error]` and is recorded in `execute()` rather than inside `runActions()` because only `execute()` knows whether a retry is still coming.
- `WorkflowsController::exportRoom()` must redact through the same `redactActions()` used for reads, and `importRoom()` must re-run `validated()` on every rule: a file is a client, and a document that skips validation could introduce a tree or an action the editor cannot produce. `uniqueName()` appends a numeric suffix instead of failing, because importing the same file twice is a legitimate check.
- `worker` is a single process: order between runs of one request is `id`, but with several replicas it is only "roughly" ordered. `recoverStale()` requeues `running` rows older than `ROUTING_STALE_MINUTES` (5), which is the only thing that repairs a killed worker.
- **Failure alerting lives in the worker, not in the catcher.** `WorkflowEngine::execute()` calls `WorkflowAlerting` only after a *terminal* outcome: a rescheduled attempt must not count, or one incident would trip the threshold by itself. `consecutive_failures` is incremented with `= consecutive_failures + 1` in one statement (not read-then-write), and the pause is `UPDATE … WHERE id = :id AND enabled RETURNING id` so two workers cannot both claim the pause. `success` resets the streak; `skipped` deliberately changes nothing (the rule never ran). A refused `forward` URL is terminal (no retry), which makes it the cheap trigger for tests.
- `disabled_reason`/`disabled_at` are set **only** by the automatic pause. `POST /api/workflows/{id}/toggle` and an `enabled: true` edit clear both plus the streak, because that is the operator saying "fixed" — leaving the streak would pause the rule again on the very next failure. `auto_paused` is derived (`!enabled && disabled_reason`), never stored, so a manual pause and an automatic one stay distinguishable without a second flag to keep in sync.
- `ALERT_WEBHOOK_URL` is best effort and never throws past `workflow.php`'s own `try`: a failed alert is `error_log`-ed and the run keeps the status already written. It is checked by `UrlGuard` too — the value comes from the operator's environment, but a typo must not become an SSRF into cloud metadata. `ALERT_COOLDOWN_SECONDS` (900) throttles "still failing" messages via `workflows.last_alert_at`; the `workflow.paused` notice ignores the cooldown because it happens once per streak and is the message that explains the stop.
- One `ws` process = one node. Horizontal scaling needs a shared broker (Redis pub/sub); each replica gets its own `LISTEN` notification.
- WebSocket auth is `POST /api/ws/ticket` → 60s JWT with `scope: ws`. Browser `WebSocket` cannot send headers, and the 12h JWT must not go in the query string; `/api/ws` has `access_log off`.
- `/hook/{x}` is ambiguous (room vs endpoint). `WebhookController::resolveTarget()` resolves it: a known room slug wins, otherwise the segment is an endpoint of room `default`. `/hook/{room}` with no endpoint stores `endpoint = 'default'`; an unknown room in a two-segment URL is a 404 — never auto-create a room or fall back.
- Room slugs are unique case-insensitively (`rooms_slug_lower_uniq` on `lower(slug)`) and validated by `RoomsController::validSlug` (`^[a-z0-9][a-z0-9-]{0,63}$`). A new slug is two 12-hex groups joined by a dash (`generateSlug`, e.g. `785e9e9c1b10-9a7be406d763`) and is never derived from the room name.
- `rooms.endpoint` (migration `003`) is generated by `RoomsController::generateEndpoint` (`hook-` + 6 hex) when a room is created without one. It changes only when the client sends `endpoint` explicitly, and an explicitly empty value regenerates it. Do not reintroduce a literal `my-endpoint` fallback in the SPA — read `room.endpoint` from the rooms store. Ingestion intentionally accepts any endpoint, so the column never gates `WebhookController`.
- Slugs are random, not derived: `utils/slug.js` (`randomSlug`, two 12-hex groups) generates one for the create form so it can preview the address, and the SPA sends it; `RoomsController::store` falls back to the same generator when it is missing. A duplicate slug is never auto-resolved: `assertSlugFree` (plus the unique index, which maps `23505` to the same answer) returns 422 «Slug комнаты уже занят, сгенерируйте новый» so the client draws a new one. The edit form shows the slug disabled and does not send it.
- A room's slug changes only when the client sends `slug` explicitly (API only; an empty value regenerates one) — renaming must not silently break external integrations. The SPA follows the slug the API returns after an edit. Existing slugs (including `default`) are never migrated.
- Workflows cannot move rooms: `update` returns 422 if `room_id` differs, because it would silently change which webhooks fire. `store` requires `room_id` or `room` (slug).
- `?room=<slug>` on `/api/requests`, `/api/stats` and `/api/workflows` is optional (no `room` = installation-wide) but an unknown slug is a 404, not an empty list. `?slug=` on `/api/rooms` is the opposite kind of lookup: 200 with an empty list, because the SPA asks "does this room exist" when resolving a deep link.
- `GET /api/rooms` is a **page**, not the whole table (20 by default, 50 for a search, `limit` clamped to 100). The counter laterals must stay inside the `LIMIT`-ed subquery: a top-level `LIMIT` still evaluates them for every room before sorting, which is exactly the cost the page is meant to avoid. Do not "simplify" it back to `FROM rooms r ... ORDER BY ... LIMIT`.
- The sidebar keeps the open room in the page (`pinnedSlug`): an old room is re-fetched with `?slug=` after each load, so its header, highlight and counters survive a reload. Search matches live in a separate `results` list — putting them into `rooms` would make `find(activeSlug)` answer `null` while the user types, and the page header would lose the room.
- `fallbackSlug()` must only return a room that is in the loaded page. Returning a remembered slug that is not there makes `/` redirect to a deleted room, and the guard redirects back, forever; the guard clears the remembered slug when `ensure()` confirms it is gone.
- Realtime events carry `room_id`; each view ignores events for other rooms. Do not add a polling timer as a substitute — a missed event is covered by the `resync` event.
- `backend/` is baked into the image: after editing PHP or adding a migration, `docker compose up -d --build api ws worker` before `docker compose exec api php migrate.php`, otherwise the new SQL file is not in `/var/www/backend/migrations`.
- Migrations that truncate (like `002_rooms.sql`) run once; `schema_migrations` prevents a re-run, so a volume already on `002` will not be re-truncated.
- **Login/`/api/auth/me` read the role from `users` on every request**, so `Auth::user()` must join/select it: a role cached in the token would make a demotion wait for the 12h expiry, which is the whole reason it lives outside the JWT. `Auth::requireUser($request, true)` is the single write gate and refuses `viewer` and `scope: read` with the same `403`; do not add a second check in a controller — a new mutating handler that forgets it is a hole.
- `Auth::requireAdmin()` is separate from the write gate on purpose: an `editor` may do everything in the product, but `/api/users*` is `admin`-only, because an editor who could grant themselves `admin` would make the roles decorative. Guards against losing access (self-demote, self-delete, last admin) belong in `UsersController` and are `422`, not `403` — the caller is allowed to manage users, just not this one.
- Do not journal a password: `Audit::diff()` is fed by `UsersController::auditable()`, which must never include `password_hash` or the submitted value. Only `password_changed` is recorded.
- `Audit::record` is best-effort and must stay that way: it runs after the change is committed, so a thrown exception there would answer `500` about something that did happen. Never let it be the thing that decides whether a mutation succeeded.
- `Audit::shape()` has two thresholds for different reasons: `MAX_INLINE_BYTES` (600) keeps a nested structure verbatim so a condition edit is visible as `"y" → "z"` instead of «count unchanged», and `MAX_CHANGES_BYTES` (4000) replaces a whole diff with `{"_truncated": …}` rather than a partial excerpt that reads as complete. Redact **before** building the diff, not after.
- An audit row copies `actor_email`, `actor_role`, `room_slug` and `object_label` at write time and its FKs are `ON DELETE SET NULL`. Do not "normalize" those into joins: the point is that the entry still explains a deleted room or a renamed account, and `?room=` matches the copied `room_slug` for exactly that reason.
- A version restore is `INSERT`, not `UPDATE`: the current configuration is snapshotted first so the rollback is itself undoable, and `change` records `rollback` so the history reads as a sequence of saves. Erasing the versions in between would answer "what did it look like" but not "who put it back".
- `workflow_versions` stores `conditions`/`actions` with signature secrets intact — a restored signed forward must still sign. Reads of a version go through `redactActions()` exactly like reads of the rule; adding a new read path means remembering that redaction.
- `workflow_versions` is read with `LIMIT 100` and is not pruned: the history is bounded at read time, so an old rollback target is never destroyed by housekeeping. If pruning is ever added, it must keep the newest rows per workflow and the `baseline` — a deleted baseline would remove the only snapshot that exists for rules that predate history.

## Conventions
- API success shape `{"data": …}` (lists add `meta`); errors via `Response::error` → `{"error":{"message":"…"}}`.
- Register routes in `backend/public/index.php`; handlers take `(Request $request, array $params)`.
- Pagination: `page` ≥ 1, `per_page` 1–100 (default 25).
- Frontend always calls relative `/api/...` paths; the Vite dev server proxies `/api` and `/hook` to `:8080`.
- SPA routes are room-scoped: `/rooms/:slug` (requests) and `/rooms/:slug/workflows`; `/` redirects to the last room (`localStorage.wr_room`) or the first one, and the guard in `router/index.js` resolves a deep link through `rooms.ensure()` (the room may be older than the sidebar page) and only redirects when the API confirms it is gone. Add new pages under `/rooms/:slug/...` and register the room in `AppShell.vue`'s `nav` so the sidebar highlights it.
- `stores/rooms.js` is the single source for the room list and slug→room lookup; it is reset on `auth:logout` so a new session never inherits the previous one's rooms. It holds **two** lists on purpose: `rooms` (the latest page plus the open room) and `results` (search matches). `find()` and every page header read `rooms`, so a sidebar search never makes the open room unresolvable.
