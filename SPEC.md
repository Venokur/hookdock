# ТЗ: приём, логирование и маршрутизация вебхуков

> Исходное задание проекта. Источник истины по требованиям; `AGENTS.md` — краткие инструкции для агентов.

Разработай веб-приложение для перехвата, логирования, визуальной обработки и маршрутизации входящих данных (Webhook, POST, GET запросы и т.д.), вдохновленное сервисами вроде Albato и Zapier.

## 🛠 Технологический стек
- **Frontend:** Vue 3 (Composition API, `<script setup>`), Vite, Pinia, Vue Router, Tailwind CSS или PrimeVue (для аккуратного и современного UI).
- **Backend:** PHP (желательно современный подход: нативный PHP с миграциями, либо легковесный роутер / микрофреймворк), работа с БД через PDO.
- **База данных:** PostgreSQL.
- **Окружение:** Полная контейнеризация через Docker и Docker Compose (отдельные контейнеры для Nginx/Apache+PHP, Node.js/Vite для сборки фронтенда или раздачи собранного статического фронта, и PostgreSQL).

---

## 📋 Основные требования и функционал

### 1. Архитектура и запуск через Docker
- Проект должен подниматься одной командой: `docker compose up --build`.
- Структура проекта должна включать:
  - `/backend` (скрипты приёма вебхуков, API для работы с правилами и логами).
  - `/frontend` (исходный код Vue 3 приложения).
  - `/docker` (конфиги для Nginx, Dockerfile'ы).
  - `docker-compose.yml` со всеми необходимыми сервисами, сетью и персистентными томами (volumes) для PostgreSQL.

### 2. База данных и Авторизация
- **Таблица пользователей (`users`):**
  - Обязательно создай миграцию или SQL-скрипт инициализации, который автоматически создает администратора:
    - **Email:** `admin@hookdock.local`
    - **Пароль:** `123456` (хеш пароля должен быть корректно сохранен, например, через `password_hash`).
- **Таблица входящих логов (`incoming_requests`):**
  - ID, метод (POST, GET и т.д.), путь/эндпоинт, заголовки (Headers), тело запроса (Payload в формате JSON), IP-адрес отправителя, дата/время получения.
- **Таблица сценариев / правил маршрутизации (`workflows` или `rules`):**
  - Управление правилами обработки (условие по пути/параметрам и действие: например, переслать дальше, сохранить, трансформировать).

### 3. Бэкенд (Прием запросов и API)
- **Эндпоинт-ловушка (Webhook Receiver):**
  - Бэкенд должен принимать любые входящие запросы (например, на `/api/webhook/{endpoint_id}` или произвольный путь) и сохранять их в PostgreSQL с полной детализацией (метод, headers, body).
- **REST API для фронтенда:**
  - Авторизация (Login/Logout по JWT или сессиям).
  - Получение списка входящих запросов (с пагинацией и фильтрацией).
  - CRUD-операции для управления правилами обработки данных.

### 4. Интерфейс (Frontend)
- **Страница авторизации:** Форма входа под учетную запись `admin@hookdock.local` / `123456`.
- **Дашборд / Лог входящих запросов:**
  - Таблица в реальном времени (или с кнопкой обновления), отображающая входящие POST/GET запросы.
  - Возможность кликнуть на запрос и посмотреть его детальное содержимое (JSON-тело с подсветкой синтаксиса, заголовки).
- **Конструктор сценариев (Интерфейс в стиле Zapier / Albato):**
  - Визуальный интерфейс для настройки правил:
    1. **Триггер:** Источник (например, входящий webhook по определенному URL).
    2. **Фильтрация / Условия:** Выбор параметров из пришедшего JSON (через простой интерфейс или JSONPath), определение логики (если поле равно X).
    3. **Действие:** Что делать с данными дальше (например, отправить POST-запрос на внешний API, записать в лог, трансформировать поля).
